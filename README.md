# Stata software documentation site

Source for <https://tdmize.github.io/stata/> — the documentation pages for
`mecompare`, `suest2`, `metest`, `meinequality`, and `totalme`. Each package
has its own sidebar and its own URL (`/stata/mecompare/`, `/stata/suest2/`, …),
so each can be embedded on its own page of trentonmize.com.

Built with [Quarto](https://quarto.org). The Stata output on the pages is real:
`build.do` runs the code in Stata (via Stata's `dyntext`) and writes it into the
pages, so re-running the build after a command changes refreshes every example.

## How the pieces fit

```
stata/
├── _quarto.yml          site config: one sidebar per package, theme, filters
├── theme.scss           colours, fonts, the command/output block styling
├── stata-run.lua        turns dyntext output into command + output blocks
├── build.do             THE BUILD: dyntext every page, then quarto render
├── index.qmd            landing page (list of packages)
├── mecompare/
│   ├── _src/            <- EDIT THESE: page sources with <<dd_do>> tags
│   │   ├── index.qmd
│   │   ├── getting-started.qmd
│   │   └── examples/*.qmd
│   ├── index.qmd        <- generated by build.do, do not edit
│   ├── getting-started.qmd
│   ├── examples/*.qmd
│   └── fig/             graphs exported by <<dd_graph>> (if any)
├── suest2/  metest/  meinequality/  totalme/     same layout, one page each
├── docs/                the rendered site; GitHub Pages serves this folder
└── tools/preview_nostata.py   render without Stata, for layout checks
```

**Edit only the files under `_src/`.** The `.qmd` files next to them are
what `dyntext` writes out (code plus output) and are overwritten on every
build.

## Everyday workflow

1. Edit or add a page in `<pkg>/_src/` (plain Markdown; see "Writing a page").
2. In Stata:

   ```stata
   cd "C:\path\to\stata"
   do build.do mecompare        // or:  do build.do   (all packages)
   ```

   This runs the Stata code in every page of the package, writes the finished
   pages, and renders the site into `docs/`. Errors in the Stata code stop the
   build at the offending page, so nothing broken gets published.
3. Look at `docs/mecompare/index.html` in a browser (or run `quarto preview`
   in a terminal at the repo root for live reload while editing text).
4. Commit and push. GitHub Pages picks up `docs/` within a minute or two.

   ```
   git add -A
   git commit -m "mecompare: add by() example"
   git push
   ```

### Small edits (wording, a sentence, a typo)

The page you edit is in `_src/`; the page the site is built from is the
generated copy next to it. So even a wording change has to go through
`dyntext` once. Rebuild just that page rather than the whole package:

```stata
do build.do mecompare/_src/examples/mediation.qmd
```

That reruns only that page's Stata code (seconds), re-renders the site, and
you push as usual. Several pages can be listed on one line. Editing the
`_src` file on GitHub's website works too, but the site will not change until
someone runs the build locally, so prefer editing locally.

### Other build modes

`do build.do mecompare norender` regenerates output without rendering;
`do build.do render` renders without touching the output (for changes to
`_quarto.yml`, `theme.scss`, the filter, or the root `index.qmd`, none of
which go through `dyntext`).

Whatever version of each command is first on the adopath is the version that
produces the output. Check with `which mecompare` before building for a release.

## Writing a page

A page is a `.qmd` file: a YAML header, then Markdown. Stata code goes inside a
`stata-run` fence with `dd_do` tags:

````markdown
---
title: "Effects within levels of a moderator"
subtitle: "The by() option"
---
<<dd_version: 2>>

One paragraph saying what the example shows.

```{.stata-run}
<<dd_do>>
sysuse nlsw88, clear
quietly logit union i.collgrad##i.south c.age, vce(robust)
estimates store m
mecompare i.collgrad, models(m) by(south)
<</dd_do>>
```

A sentence or two on how to read the result.
````

When `build.do` runs, `dyntext` replaces the `<<dd_do>>` block with the
commands and their output exactly as Stata's Results window shows them. The
`stata-run.lua` filter then splits that into a syntax-highlighted command block
(with a copy button; the `. ` prompts are stripped so the copied code runs) and
an output block underneath, repeating for each command that produced output.
Commands with no output (`quietly ...`, `estimates store`) are grouped together.

Useful tags (all documented in `help dyntext` / `help dynamic tags`):

| Tag | Effect |
|---|---|
| `<<dd_do>>` … `<</dd_do>>` | Run the code; show commands and output. |
| `<<dd_do: nooutput>>` | Show the commands only (e.g. for data preparation). |
| `<<dd_do: nocommands>>` | Show the output only. |
| `<<dd_do: quietly>>` | Run the code without producing output (see `help dynamic tags` for how it differs from `nooutput`). |
| `<<dd_graph: saving(fig/name.png) replace width(700) markdown>>` | Export the current graph to `fig/` and insert it. Use it right after the graph command, *outside* the code fence. |
| `<<dd_display: %5.3f r(mean)>>` | Insert a number into the prose. |

Put `<<dd_version: 2>>` right after the YAML header of every page (it is
removed from the output). Keep one idea per page; the sidebar does the
organising.

Static code that should not run (installation lines, syntax diagrams) goes in
an ordinary fence:

````markdown
```stata
net install mecompare, from("https://tdmize.github.io/data") replace
```
````

### Adding a page to the sidebar

Pages appear in the sidebar only if they are listed in `_quarto.yml`. Under the
package's sidebar, add the path of the *generated* file (the one next to
`_src/`, not inside it):

```yaml
        - section: "Examples"
          contents:
            - mecompare/examples/mediation.qmd
            - mecompare/examples/moderators.qmd      # new
```

Sections can nest, so `mecompare` can grow into "Examples", "Options",
"Comparing groups", … each with sub-pages. Quarto's sidebar documentation:
<https://quarto.org/docs/websites/website-navigation.html#side-navigation>.

### Adding a package

Make `<pkg>/_src/index.qmd`, add a sidebar block for it in `_quarto.yml`
(copy an existing one), and add `<pkg>` to `all_pkgs` in `build.do`.

## Look and feel

- `theme.scss` — colours, fonts, spacing, and the styling of the command and
  output blocks. The `scss:defaults` section sets Bootstrap variables (the
  `cosmo` theme is the base); `scss:rules` is ordinary CSS.
- `_quarto.yml` → `format: html` — page outline position (`toc-location`),
  column widths (`grid`), code highlighting style, copy buttons.
- The left sidebar stays docked down to 860px of width (Bootstrap's default is
  992px) so that it survives being embedded in a Google Sites page; below that
  it collapses into a menu button. This is the `$grid-breakpoints` setting in
  `theme.scss`.
- The page outline ("On this page") sits under the navigation on the left,
  which keeps the text column wide at embed widths. `toc-location: right` in
  `_quarto.yml` gives the marginaleffects.com three-column look instead.

## Previewing without Stata

`python tools/preview_nostata.py --serve` renders the site into a temporary
folder with placeholder output in place of the Stata results and serves it at
<http://127.0.0.1:8765/mecompare/>. Nothing in the repository is touched. Useful
for checking prose, links, and navigation on a machine without Stata.

## One-time setup

1. **Quarto** — install from <https://quarto.org/docs/download/> (the Windows
   installer puts `quarto` on the PATH). RStudio also bundles it, but the
   standalone install is simpler for `build.do`.
2. **Repository** — create `tdmize/stata` on GitHub, push this folder to it.
3. **GitHub Pages** — repo *Settings → Pages → Build and deployment*: Source
   "Deploy from a branch", branch `main`, folder `/docs`. The site appears at
   <https://tdmize.github.io/stata/> after the first push.
4. **First build** — `do build.do` in Stata, commit, push.
5. **Google Sites** — on each software page, *Insert → Embed → By URL* with the
   package URL (e.g. `https://tdmize.github.io/stata/mecompare/`), stretch the
   embed to the full width of the section and give it a tall fixed height. Or
   simply link to the URL; the pages stand on their own.

## Notes

- Row numbers in `metest` examples refer to the `#` column of the table
  printed just above them; check them when a command's table layout changes.
- The dataset URLs (`https://tdmize.github.io/data/data/...`) are loaded at
  build time, so the build needs network access.
- `build_render.log` holds Quarto's output from the last build (ignored by git).
- Search across the site is built in (the magnifier in the sidebar); it
  indexes the rendered text, including Stata output.
